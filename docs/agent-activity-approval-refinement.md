## Corrections

- Replace the tall agent/run metadata header and visible full-width progress display with one compact title/status/menu row. Keep the accessible progress semantics and tested status focus in the footer without a second visible dashboard header.
- Show all eight original workflow rows and completion continuously by default, rather than hiding completed steps behind a finished-step disclosure. A footer history action restores finished rows if the user enables folding.
- Place the active approval/question and its real action field inside its trace row. Revision retains focus, Cancel, blank Send validation and the existing decision/skip behavior.
- Keep secondary paths beneath titles on narrow screens, action icons visible there, and durations right-aligned. The outer card uses a 576px maximum with 24px narrow-screen insets.
- Implement observed menu defaults: File Paths on, Step Notes off, Fold Finished Steps off, Comfortable selected. The local controls really hide paths, reveal supporting notes, fold finished rows and reduce spacing. Copy Summary and Restart retain their existing behavior.

## Deliberate remaining differences

This is a structural refinement, **not a pixel-match or full-lifecycle fidelity claim**. The pending completion row says “Complete the run”; “Run complete” is reserved for actual completion so the visible status cannot announce success prematurely. The independent model still starts at the third-step approval; the observed reference starts running and reaches question five after four completed steps. Retaining that seed and existing contracts was explicitly required. Independent fixture wording, step order, counts, work durations and tool targets differ. Local elapsed time is explicitly recorded completed-work duration, not a live wall clock. The original working phase can show “2 more after these”; this refinement keeps its local future steps visible. Completion uses a simple ninth Marker rather than reproducing all reference skipped/check/changed counts or an extra final issue fixture. Original revision reasons and provider labels are represented by the independent model's decision notes and skipped state. Open-target actions explain local-demo scope instead of opening a real repository or external tool. The original alternative view/density result, clipboard success, Approve/Deny and pause/resume are still pending. Local functional test success does not fill those public-evidence gaps.
