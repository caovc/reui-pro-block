## Actual official free reuse

Before implementation, the CLI fetched and the source was read for all10 `@reui/c-dialog-1…10` examples, plus `c-select-11`, `c-accordion-1`, `c-toggle-group-1`, `c-icon-tile-8` and `c-input-group-32`. REUI's free Dialog page explicitly categorizes Dialog as an upstream shadcn/ui component and installs/consumes that component. The installed `src/components/ui/dialog.tsx` therefore supplies the actual free implementation: Radix portal, overlay, focus scope, Escape/outside dismissal, close control, Title and Description. No overlay or focus implementation is redrawn.

Owned `free/dialog-surface.tsx` composes that actual component using the real free `c-dialog-3/6` header → independently scrolling body → fixed footer structure. Provenance and MIT notices are retained. Adapters expose content/media/footer slots, per-entry width, viewport bounds, the cancellation Keep-plan focus target and a delegated inline-editor Escape guard. Placeholder Lorem Ipsum and fixed example buttons are replaced by domain content; this is a documented composition adaptation, not a claim of byte-identical source. Sources: <https://reui.io/r/radix-nova/c-dialog-3.json>, <https://reui.io/r/radix-nova/c-dialog-6.json>.

- **Official IconTile:** existing complete `src/components/reui/icon-tile.tsx` paints actual frame/soft geometry, inset/pseudo layer and sizing. Used for duration header, checklist section headers, category tiles and launcher scenes. No hand-drawn tile surface is substituted.
- **Official Badge:** existing actual free `badge.tsx` supplies Workspace access, checklist statuses, team/tags, duration summary and launcher status. Real variants are consumed.
- **Official Alert:** existing actual free `alert.tsx`, including AlertAction, supplies the cancellation warning and responsive management actions, local feedback and app-management notices. No custom callout replacement.
- **Official Frame:** actual Frame/Header/Panel/Footer supplies useful closed launcher scenes. Initial dialogs stay closed as directed for the gallery, while each launcher opens the full observed composition. This deliberately differs from the reference's initially open state.
- **Upstream primitives as consumed by free examples:** Dialog1/2 follow free `c-select-11`'s Select-with-Dialog composition; all SelectItems live in SelectGroup. The real `c-accordion-1` single/collapsible/default-open arrangement drives the checklist, and the installed Accordion handles keyboard expansion. ToggleGroup provides actual single-choice state/focus; RadioGroup provides the category rail. Field/FieldGroup/FieldSet, InputGroup, Item, ScrollArea, Checkbox, Input/Textarea, Button, Tooltip and Empty are consumed rather than recreated.
- **Artwork:** existing original `demo-artwork.ts` supplies all template thumbnails and typographic app marks, through its actual `demoPanel`, `integrationArtwork` and `svgImage` helpers. The shared helper is not edited. No binary assets, logos, portraits, vendor SVG files or new dependencies are introduced.

The installed shadcn Dialog/Field documentation and Radix Dialog API were fetched after `npx shadcn@latest docs dialog field`. Existing sources/APIs were inspected before composition. The free registry searches for editable/email capabilities were reviewed; they expose primitives/examples, but no equivalent standalone inline-text draft editor or bulk-address validator. Those missing domain behaviors are implemented locally below.

## Custom domain gaps and limits

Free Dialog examples supply modal mechanics and slots, not48slot duration arithmetic, deduped/validated invitations, cancellation reason persistence, editable checklist records/app authorization, or a domain template catalog. Custom code only covers those data transitions and the observed arrangement. Existing components retain their actual accessibility/interaction behavior.

All saved outcomes last only while the preview is mounted. No event creation, email delivery, membership grant, subscription cancellation, payment change, OAuth consent, remote project creation or settings API exists. The UI identifies local results without requesting credentials or representing a fixture as a live service. The cancellation survey is a reversible local preview; its primary action never contacts billing.

Intentional visual differences are closed initial overlays with supporting launch scenes; original SVG thumbnails/app initials; a local example escalation email; and readable mobile inline editors. The original template rail/list topology is retained while keeping the footer reachable on short screens. Exact reference images are neither retrieved nor bundled.
