# Lucent Services and utility navigation · 12 November 2026

This is an independent Bricklane reproduction. This batch corrects Services navigation against a fresh public-reference observation and preserves the separate local release-review flow. It does not establish complete Lucent sidebar or toolbar fidelity.

## Evidence and resulting behavior

The previous four Services rows and three utility rows were manually composed `Button` elements. The utility rows shared the same Settings icon and had no current-page state. All seven rows disappeared when the sidebar collapsed. A fresh desktop inspection confirmed that selecting `api-gateway` opened the generic release-approval Sheet, including an `Approve change` action.

The existing deployment ledger also generated version, environment, status and owner from the index **after** filtering. Searching for `orders-db`, for example, reassigned the first row's `v3.14.0`, `Degraded` and Marcus Webb values to that service. The fixed catalog retains the exact original unfiltered fixtures; filtering now selects complete service records.

Fresh public-browser observation at 1440×1000 and 390×844 confirmed a real, initially open Services disclosure. Its four rows are ordered `api-gateway`, `recommender`, `orders-db`, `edge-cache`, with Degraded/yellow, Healthy/green, Down/red and Healthy/green indicators. Each row exposes its health and `Open service details` in its accessible name, plus a separate Actions menu. Click and keyboard Space/Enter toggle the group. Both viewports expose Details, Copy name, Pin to top and Remove. Only read-only menus and details were exercised on the public site; its Pin/Remove behavior and backend were not tested.

Expanded Services now consumes the actual `SidebarCollection` implementation from `src/components/reui/sidebar.tsx`: its existing free Collapsible/Trigger/Content and SidebarGroup/Menu/MenuItem/MenuButton composition supplies the disclosure and separate action slots. Collapsed Services consumes the actual `SidebarNavigation`, retaining its native accessible names and tooltips. The shared Shell's existing `retainExtraWhenCollapsed` option keeps these consumers available in the icon rail. Utilities retain `SidebarNavigation` current-page state; Integrations, Security and Settings use Plug, Shield and Settings icons. Account pages clear the previous workspace current item.

Each service now opens its own read-only free Sheet, preserving the underlying workspace and URL, as observed publicly. The public Sheet has a floating panel with 16px outer spacing and a maximum width of 480px; the local consumer uses that structure. The local name, version, environment, health and owner still come from the existing local ledger catalog and are explicitly labeled `Local demo service`. Public Runtime, alert and release records are not copied into this catalog. In particular, the public api-gateway Sheet shows v2.14.0 and two open alerts, while the pre-existing local ledger fixture is v3.14.0; the local Sheet does not pretend that these are the same backend records. Its View deployments button opens the existing local Delivery page. The separate person-based release-review Sheet and local approval state remain intact.

The menu is labeled `Local pinned services`. Copy name writes the actual clipboard and reports failure truthfully. Pin to top and Remove update only the local pinned list, without deleting the service or ledger data. The list lives above the mobile drawer so these local changes survive closing and reopening navigation. Remove offers Undo. These operations are local demo behavior, rather than a claim about the untested public backend.

Sheet close restores a connected, visible opener. If View deployments replaced the ledger and unmounted Inspect, focus falls back to a visible current navigation item or the visible mobile navigation opener. The prepared regression exercises the actual Observability → Inspect → View deployments path, as well as Escape preserving the ledger's search and returning focus to Inspect.

The related production regression exposed a separate mobile account obstruction: after Preferences Save and returning to Profile, the native bottom-right notification covered Cancel and intercepted its original five-second click budget. The first failure trace and a frame showing the overlap are retained under `/tmp/lucent-qa-current/related-native/lucent-account-layout-nati-db294-ent-Billing-and-Preferences/`. Sonner supports pausing on hover, but this trace did not prove sustained hover; the observed defect is the bottom toast's lifetime overlapping the footer action.

A top-center positioning candidate was tested on `http://127.0.0.1:5200` and failed the unchanged mobile case earlier, at the Preferences tab: top toasts intercepted the target, and the existing sticky header also appeared in the hit-test log. This candidate is not a successful fix. Its trace, error context and extracted frame remain under `/tmp/lucent-qa-current/toast-fixed/original-failure/`; the other nine account native cases passed in 1.4m. The final approved narrow correction restores the original inherited bottom-right position and adds only `style: { pointerEvents: "none" }` to the seven existing, purely informational Lucent account notifications. Their native visual feedback, aria-live behavior and lifetime remain. No global Toaster, actionable/Undo toast, header, account data behavior, test budget or click mechanism changes.

The final correction passed on production candidate `http://127.0.0.1:5210`: first the exact original mobile failure case passed in 14.1s, then the other nine account native cases passed in 1.1m. All ten retained their original assertions and budgets; there were no retries. A passing trace was explicitly retained for the mobile case. Its DOM records show `pointer-events: none`, bottom/right position and the existing polite aria-live region. The first Preferences tab click completed in about 191ms and the first Cancel in about 207ms, with no header change. The trace had no application console warnings or errors. The trace, extracted phone frames and `passing-toast-proof.json` are under `/tmp/lucent-qa-current/pointer-events-fixed/original-failure/lucent-account-layout-nati-db294-ent-Billing-and-Preferences/`. The notification remains visible in the successful Cancel frames, demonstrating that the action no longer waits for its dismissal.
