## Controlled integration contract

Parent owns Drive leaf, route adapter, SourceTargets and source collector. `DriveSettings` accepts `section`, optional `memberSlug`, mounted `model`, `navigation`, actual `files`, `onOpenFile`, `pricingHref`, and `onPricing`. The navigation interface provides `href(section, memberSlug?)` and `onNavigate(section, memberSlug?)`; this implementation never reads or writes window.location. Genuine anchors preserve modifier/middle clicks. Parent routes preview/isolated/standalone hashes, retains original theme query parameters, and implements Back/Forward/Refresh without remounting the template. The host keys only the current page, so route-local drafts/media are discarded while mounted saved text remains.

Call `useDriveSettingsModel({onProfileNameChange, onWorkspaceNameChange})` once in the parent leaf. Profile name feeds DriveLayout/profile menu; workspace name feeds the existing header WorkspaceSwitcher. The Layout API is only `activeApplication?`, `profileName?`, `profileMenu?`, preserving defaults when absent. The profileMenu slot is inside the existing SidebarProvider. Its default avatar stays the original local Alex graphic. Workspace name is not a broad Layout identity API.

`DriveProfileMenu` consumes controlled name/email/theme/onThemeChange/navigation/loginHref/onSignOut. Native Dropdown anchors close on normal selection; on phone their existing useSidebar closes the same 63px Sheet. Theme uses the existing RadioGroup and keeps the menu/Sheet open. No custom Escape/focus code is added to this menu. Pure Escape must first return to the avatar, then close Sheet to Toggle Sidebar; route selection must close both to Toggle Sidebar. These are pending actual main tests. Sign Out delegates a local login route; it does not claim server authentication changes.

Main rail visible labels Drive/Workspace/Pricing/Settings map the original action strings Drive/Workspace settings/Get More Storage/Account settings. Active application must follow the controlled route instead of hardcoding Drive. The original file models/dialogs remain parent-owned. Member detail consumes actual Drive file records and calls the existing file-detail callback; it does not introduce a generic replacement file drawer.

Pricing is an explicit callback/href integration boundary. Reference Manage plan/Review plans navigate to pricing, not a modal. Parent must bridge its actual pricing consumer; the old two unrelated plan buttons do not satisfy that requirement. Pricing Switch behavior was not activated in the reference and must not be invented as external charging.

## State and behavior boundaries

- Profile Details and Preferences each have independent Save/Cancel. Workspace Details has Preview brand/Save and no Cancel; Preferences has its own Save/Cancel. Preview brand reads the current draft.
- Saved text/preferences persist through SPA navigation in the mounted model. Cancel returns to that card's last saved values; refresh resets fixtures. Profile/Workspace saved name callbacks are narrow text updates.
- Upload/removal is entirely page-local. Cancel affects text only; uploaded/removal preview remains. Route unmount restores the default photo/logo. Save does not synchronize or persist media.
- Team has nine initial rows, Active6/Invited1/Limited1/Suspended1, search AND selected statuses, initial Member ascending, page sizes5/10/25/50/100, responsive job title under Member. Native role dialog has all three access roles; Owner's five actions are enabled, Remove destructive.
- Team mutations are explicitly local simulations: invitation inserts an Invited record and says no email was sent; role updates the local row, reset increments a local counter, remove actually changes the collection with Undo, Copy uses the real clipboard. The reference audit inspected these controls but did not submit mutations; these are not claimed as observed server outcomes. Other members' unobserved Location/Joined show an em dash rather than fabricated personal data.
- Billing Setup Save stores its own snapshot; seat cards are mutually exclusive16/24/40/null despite their checkbox presentation. Initial none selected.
- Billing Controls has no Save/Cancel. Its own state resets to false/true/2500/Weekly summary on unmount. It never silently updates the saved setup snapshot.
- Approvals and invoices are actual separate Dialog contents (3 and5 records). Approval/denial is marked local only and visibly changes the local pending list; no external approval or payment request. Statements/invoices generate local PDF content with clear local/noncharging text.
- Text toast specificity and actual visible/menu density need final reference comparison. A successful static lint is not evidence of visual fidelity.
