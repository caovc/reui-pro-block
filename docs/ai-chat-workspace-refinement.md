## Application gaps and remaining differences

Free examples do not contain a complete quote-aware thread controller, immutable integration permission/receipt workflow, editable ordered task plan with intentional failure and mid-run branch, or a local ticket/file handoff. The new reducers implement those specific gaps. They use original fixtures and in-memory state, with no external AI/tools, persistent storage, OAuth, microphone or real issue tracker. Changing a source grant never silently adds evidence to a completed answer. An explicit Connect action replays a skipped receipt before it becomes read.

The source-limited/quoted composer and answer-slot transcript are new helpers because the first milestone's frozen APIs expose neither per-entry source restrictions nor quoted/plan controls. The frozen helpers are not overwritten. Their real upstream primitives and REUI free patterns are reused; optional backward-compatible consolidation can be coordinated after publication.

Local production, source/export and actual downloaded-project checks will be recorded here when complete. Green tests alone will not change the public visual status to verified.

## Verified compatibility correction in the reused free Combobox

The retrieved c-combobox-26 source manually maps all option children under a root `items` array. In the installed Base UI 1.9 implementation, those static children remain all nine rendered options after typing “Zoom”, so the highlighted index could incorrectly toggle Drive. This was reproduced in the actual new mobile AppScope, not inferred from a visual resemblance.

The local adaptation preserves the actual free controlled multi-picker/trigger/value/search/list/item composition, but uses the installed public `ComboboxList` item render function so the primitive's filtered collection owns its children. `itemToStringLabel` supplies search/display text; `itemToStringValue` supplies the app ID for form serialization. This is supported by the installed `ComboboxList.js` closed-template implementation and the [official Base UI v1.9 API](<https://github.com/mui/base-ui/blob/v1.9.0/docs/src/app/(docs)/react/components/combobox/types.md>). No hand-built filter, keyboard handler, new package or shared Combobox change is introduced. A persistent test first asserts exactly one Zoom option, then Arrow/Enter selects Zoom and the meeting run reads its receipt.

Two additional local integration corrections preserve actual free behavior. The Sidebar's mobile `Sheet` sets its own data-side width variant, so the new leaves pass the matching mobileClassName variant rather than assuming the width variable alone overrides it; both requested mobile panels now measure the intended 390px. Only the new leaves change, not shared Sidebar/Sheet. The task footer derives its live status from the state machine, and preflight/retry/skip/fork/handoff actions move focus to that persistent status target when their prior control disappears, following the free c-trace-4 focus pattern. A regression asserts the failure status and focused live target after Retry.

Local downloaded mobile review also exposed two close icons: the custom desktop panel close button and the actual Sidebar's native mobile Sheet close. The new leaves now keep the custom close at desktop widths and reserve space for the native mobile control. Existing shared Sidebar/Sheet is untouched. Narrow-layout coverage asserts one native visible close control and the desktop-only control hidden. The Sheet measurement uses 0.01px tolerance for floating-point transform precision; a reported width of 389.9999847px is treated as the intended 390px rather than a product defect.
