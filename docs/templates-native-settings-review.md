# Echo, Flowly and Lucent native settings review

This milestone composes actual ReUI free Sidebar, Frame, Item, Field, Select, Combobox, Dialog, Sheet, DataGrid and related controls with the existing controlled Pro Settings presentation. It includes Echo's native chat Sidebar and seven inline account sections; Flowly's ten distinct settings pages and mobile secondary navigation; and Lucent's General Settings and Notification rules. Lucent document header and base mobile bounds are corrected separately. Drive's new inline settings, Flux settings, and Lucent Security/Integrations content migration are later work and are not included here.

## Actual reuse and corrections

Echo uses the native Sidebar Provider, Collection, Trigger and mobile Sheet, including the existing optional trailing-count presentation and trigger-children contract. Its real chat menu actions share stable message records with the existing scheduled-task form, search, share and export behavior. Seven settings sections use actual free Frame, Tabs, Alert, local file upload, and the existing Pro SettingsRows/Fields/Choice. General choices take effect immediately; per-card saved/draft values remain distinct. No second Sidebar Provider or generic modal substitutes for the inline settings.

Flowly composes actual free Frame and existing Pro rows/fields with the official free rich Select, timezone Combobox and NumberField examples. Its Members, Integrations and Webhooks pages use the actual native DataGrid, controlled drawers, dialog validation and domain models. Seven simple form pages do not gain invented Save/Cancel actions. The shared Shell receives five optional consumer inputs, preserving defaults: mobile secondary content/width, header title/actions, and the mobile selection close policy. The native mobile Sidebar remains the same Sheet when Settings expands from49px to249px. Its primary content remains48px and its secondary content200px including the border. Header, footer, focus and Escape remain in the same provider.

The later Flowly visual review corrected three Lucide navigation icons, the full cumulative secondary-nav spacing, and the natural footer layout across all ten pages. The secondary footer is x49/y746/w199/h98 at390×844. The primary account button remains28px and its original local avatar is24px. These corrections use measured type, line height, gap and content structure rather than a hardcoded footer height. Original Bricklane marks and local artwork replace brand assets; no reference image, paid screenshot or extracted SVG is distributed.

Lucent General uses the existing Pro SettingsRows/Fields/Choice with actual free FieldGroup/FieldSeparator, Frame, ColorPicker, ToggleGroup, file hook and Dialog. Notification rows now use actual Item/ItemContent/ItemTitle/ItemDescription/ItemActions, matching the reference structure. This replaces the earlier inappropriate form rows and fixes the mobile description-clamping difference. The free Collapsible surrounds the Frame instead of overwriting its data-slot through asChild. Reset/Save affect General only, while the two notification groups have independent immediate state and independent collapses. A consumer focus handler makes the native date-format keyboard target visible without rewriting ToggleGroup.

Lucent's existing document header was static49px and its mobile content padding12px. The separate measured correction makes its48px header sticky and mobile content padding16px. The Settings compensating margins are removed. Only a full preview containing the DevOps/Lucent root makes its own36px toolbar sticky; standalone and isolated views use top0. General frame positions and sizes remain identical. This does not replace the shared Shell or alter other template brands.

## Remaining scope

The public examples do not establish a real server backend. Local save, membership, invitation, webhook delivery and export states are explicit local behavior; no external invitation, charge or service mutation is claimed. Echo's original reference does not expose a fully dynamic organization backend. Flowly retains earlier internal editor labels even where public route names are longer. Lucent's file-import and custom quiet-window editor remain explicitly recorded gaps rather than simulated backend successes. Security/Integrations have separate existing content-density and domain-interaction differences despite the corrected header and base bounds.

The three-ID source-target change must be replayed narrowly onto the current file; it must not overwrite concurrent block/source mapping work. Actual new data, styles and reused components remain in the exported dependency graph. Commit, push and preview deployment are coordinated separately by the release owner; passing these private checks is not a deployment claim.
