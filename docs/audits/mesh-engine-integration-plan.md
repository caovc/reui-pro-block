## Reference observations

Official references: [Canvas](https://mesh-whiteboard.reui.io/canvas), [Documents](https://mesh-whiteboard.reui.io/documents?doc=DOC-1).

- Both pages have one 48px header after a 49px navigation rail. The document title is an editable body H1; the header label is Documents. A second parent header would be incorrect.
- Documents body is Inter16/28, max width640; H1 24/36, H2 20/32, H3 18/28. Small Text changes body to14/24 while retaining heading sizes. Full Width removes the640 cap and uses16px 64px 48px content padding on the measured desktop viewport.
- Doc options contains an Open Doc submenu with five document choices and update times, plus New, New from Template, Rename, Duplicate, Copy Link, Full Width, Small Text, Copy HTML/Text, Clear and Delete. The displayed document's native history and selection must remain authoritative.
- The header exposes presence, Ask AI, Share, Edit/View, Undo/Redo and Doc options. Share contains a document link, Copy, Can edit/Can view and View only. Reference AI opens a real conversational side pane with sources, feedback, copy/regenerate, suggested follow-ups, new question, settings and composer.
- Canvas starts at60%, Selection, grid/snap/view-only off. Frames, native drawing, transforms, bindings, real text, history and exports must consume the existing Block. The observed Board/Outline/Comments header choices changed selection without replacing the canvas; preserve the engine mount and history across these choices.
- Original screenshots, avatar media, original scene JSON and extracted SVG assets are excluded. The independently authored launch-map text uses the existing Block geometry and original local phone drawing.

## Narrow public contracts

1. Shell owner supplies the independently reviewed optional `headerContent?: ReactNode`: undefined preserves the entire existing header; null hides only that header; a node replaces it. Provider, content, account settings and all state remain in place. Use the owner's published996 or future-five-options narrow patch against the matching current base; never copy an older full Shell over later options.
2. Whiteboard parent gains an optional header renderer receiving only its existing page controls (scene name, readiness/saved state, view mode setter, existing exports and panel toggle), plus `initialViewOnly?: boolean` defaulting to false for view-mode preview links. Existing standalone Block examples retain their existing rendering and behavior. Mesh supplies its single Canvas header and Board tabs. No second copy of pointer, pan, hit-test, history, resize, frame or export logic remains in Mesh.
3. RichEditor gains an optional ready callback exposing the public Tiptap Editor instance to the outer Mesh toolbar. Bind its create/destroy subscriptions to the actual instance returned by `useEditor`, with exact cleanup; a temporary Strict Mode instance must never supply the outer toolbar handle. Use the instance's actual commands, state and can-undo/can-redo values; no React internals, DOM back-reference or synthetic selection mirror is used in the implementation. Default Block consumers do not provide the callback and retain behavior.
4. Navigation save flush is required for real page switching: the existing debounced editor/board saves must flush their latest captured content on unmount/pagehide, under the captured storage key, without accepting edits before readiness. Do not broaden this into SDK internals, new scene formats, library behavior, fit/style work or a new persistence framework.

## Static implementation status

The draft removes Mesh's duplicated SVG scene/gesture/history implementation and consumes the entire Whiteboard Block. The document page subscribes to the public Tiptap update and transaction events for real content and toolbar history. Switching documents intentionally creates a new editor; native editing, rename, clear, header controls and display changes preserve the existing instance. Each document opening has a distinct mount token to reject a previous document's deferred callbacks. Within the same opening, ready notification is owned by the committed hook instance; a mount token alone cannot distinguish Strict Mode's temporary editor. Document content/metadata updates save synchronously; board and standalone editor debounce queues flush captured snapshots on unmount/pagehide.

Document controls include five seed documents, new/template/rename/duplicate/delete/restore, live Contents/mentions/tasks/table/code through the shared schema, Full Width, Small Text, real Edit/View, native Undo/Redo, schema HTML/text clipboard actions and a source-aware assistant. Preview links carry actual `doc`/`page` and optional `mode=view` state; they do not create server permissions. Canvas tab changes and assistant toggles preserve the same native engine. Presence is explicitly sample data. The assistant's conversation, sources, feedback, composer, replay and settings are local preview behavior; replies derive from the document/scene supplied by the native model, without an external AI provider.

The actual ReUI `c-message-7` composition retains its pending/streaming lifecycle, permanent status region, reduced-motion behavior and mounted action footer. Its sample question and answer were replaced with content props. Existing ReUI Frame, Sidebar, Scrollspy, NumberField and ColorPicker continue to supply their real implementations. Full document/whiteboard engines remain the missing capability supplied by Tiptap and Excalidraw rather than custom substitute primitives.

## Historical17e validation and diagnosed lifecycle defects

The first5fcd integration completed a normal strict production build with exit0. Its selected38-test production gate reported28 PASS and10 FAIL. All failures passed through Documents, including the existing Mesh editor/outline compatibility case; they were real product failures, with a React185 maximum-update-depth error. The initial source and immutable production assets, error contexts and traces were retained. That result does not establish integration completion.

A console-only observation copy of the same production assets identified the exact loop: a BubbleMenu `updateOptions` metadata transaction had `docChanged=false`, `canUndo=false` and `canRedo=false`; Mesh incremented an outer history revision anyway, causing a parent render and a fresh `shouldShow` callback, which dispatched another `updateOptions` transaction. This repeated until React185. The leaf correction subscribes to all native transactions and stores the actual two history booleans, returning the previous state object when both are equal. It does not filter metadata or selection transactions. Content capture, title/metadata updates, synchronous storage and edit/view state remain independent. An equivalent isolated asset diagnostic settled after one metadata transaction without the error; this is causal evidence, not a replacement production build or formal test gate.

Strict Mode exposed a second defect in the new ready API. Two native editors could run delayed `onCreate` callbacks, although only the first was the actual committed DOM editor. The temporary second editor supplied a toolbar handle and then cleared it during its delayed destruction. Public DOM-attached editor identity was inspected only in diagnostics to establish the owner. The implementation correction instead binds the ready API to the actual editor returned by `useEditor`, using normal public lifecycle events and exact cleanup. Existing initialization, outline, document, mark and selection callbacks remain intact. In isolated development diagnostics, only the committed instance notified Mesh; real typing reached synchronous storage and native Undo/Redo remained usable.

Scoped formatting and lint checks exit0 for the narrow corrections. The corrected17e candidate completed its original production build with exit0. Its original38-case gate reported36 PASS and2 FAIL; both remaining failures were proven test fixtures: native ToggleGroup exposes radio Edit/View, and a390px navigation helper checked visibility while the lazy page still displayed a skeleton. Only these test roles and mobile readiness were corrected; all read-only, history, layout and focus assertions were retained. The two affected cases then passed once on the same immutable build. The original36-pass/2-fail run and its traces remain part of the record; this is not reported as an all-green first run.

Eleven integration tests cover native document CRUD/history, immediate navigation/reload persistence, measured typography/display/view mode, persistent Canvas mounting across tabs/assistant, drawing/export/flush, clipboard and view links, source-aware assistant actions,1024/390 layout/focus, and actual source/copy/file/ZIP parity.
