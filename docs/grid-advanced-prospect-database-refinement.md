# Advanced 22: Prospect Database first implementation

Date: 2026-10-26. This is an independent Bricklane implementation using original account fixtures. The leaf is not registered in the public catalog or dispatcher yet. Formatting, lint and domain tests are separate gates from the still-pending browser, strict-build, visual and Source/ZIP checks.

Reference: [public Prospect Database](https://reui.io/blocks/data-grid/advanced/data-grid-advanced-22). ## Actual free implementation reuse

The primary source is `grid-advanced-prospect-database.tsx`. It composes the installed official free DataGrid, DataGridTable, ColumnHeader, Pagination, ScrollArea and both native selection components. A genuine TanStack v9 `useTable({ features: dataGridFeatures })` owns raw-account filtering, sorting, pagination, visibility, order, sizing, pinning and selection. The official free [pinnable example 16](https://reui.io/components/data-grid) was read before implementation; the current registered features provide native column faceting as well.

Direct `useTable` composition is used because this consumer needs controlled column pinning and a structured global-filter value. The existing `useDomainGrid` wrapper intentionally exposes string search and does not expose a controlled pinning slice. This is a consumer composition of the same free components and features, rather than a replacement table engine or an unreviewed shared-wrapper change.

The intent summary uses the intent column's actual native faceted row model. Search, the advanced query tree and My Accounts establish its denominator; selecting an intent card further restricts the table without turning that one card into 100% of the summary. There is no manually sorted, paginated or prefiltered shadow array. Domain summary arithmetic is performed on records from the native model.

Advanced filtering uses the installed official free Filters with `FilterQuery`, `query/onQueryChange`, advanced popover mode, field picker, operator/value editors, nested AND/OR groups and negation. Eleven account fields are declared as a schema. Its domain predicate walks the actual query tree and skips unfinished rules or empty draft groups, including an empty OR branch. It recognizes the actual free catalog's `is_any_of`, `is_none_of`, `has_any_of`, `has_all_of`, `has_none_of`, range and valueless operators. It neither flattens mixed groups nor uses the old flat FilterRule adapter as a substitute.

The free Cascader's drill navigation, search, breadcrumb, multiple selection, checks and keyboard behavior drive native visibility. Firmographics, Buying Signals and Outreach form the observed three branches. Visibility is read from and written to the TanStack state alone. The installed free Frame, IconTile, NumberField and Timeline are composed directly. The free supporting Tabs, Sheet, Popover, Dialog, AlertDialog, DropdownMenu, Field, InputGroup, ToggleGroup, Select and Switch provide their actual state machines.

The current official free [Chart example 1](https://reui.io/components/chart/c-chart-1) and its actual installed ChartContainer were checked. Both the six-month headcount bars and the intent ring compose this ChartContainer over Recharts, with explicit small initial dimensions and animation disabled. No CSS imitation of the free bar-chart implementation remains. Missing headcount months remain null and are shown as gaps, including for a newly created company. The tiny ring is an intent-score visualization, with its raw score and label printed beside it; the custom domain work is its score/threshold mapping and compact geometry. Current free Progress exposes a linear indicator, and its eight current examples were checked rather than assuming that it supplies a circular intent meter.

## Original data and real mutations

Thirty original companies have stable IDs, authored numeric intent/contact/employees/revenue fields and six-month headcount arrays. The four original owners and three original lists are separate identity records. Company marks use the actual free IconTile with Lucide artwork; avatars use the repository's original `demoAvatar`. Source/font MIT/OFL notices must remain in the downloaded closure.

The original fixtures deliberately produce 10/11/9 intent bands and 7 accounts for the current owner, including 2 closed accounts. These counts let the observed filtering and handover boundaries be exercised without copying the reference's companies, financial values or chart series. Other numeric values and company identities differ intentionally. Handover currently moves five open accounts and retains Qualified/Disqualified accounts, preserving statuses, lists, contacts and signals. Its contact total is calculated from these original records and differs from the reference's total.

Owner and status menus update the same immutable book as forms, list membership and deletion. A bounded snapshot history records whole mutation batches. The visible Undo button, keyboard shortcut outside editors and replacement mutation toast operate on the latest batch. The toast uses one stable ID so an older Undo action cannot silently undo a different newer command. List creation and saving the chosen accounts are one reversible transaction. Deletion requires the free AlertDialog, removes the account's owned data, and can restore the complete record with Undo.

Add/Edit validates a trimmed name, normalized unique domain and whole employee count, including a genuine zero. Editing employees keeps the current headcount point consistent while retaining prior points. Company detail has real Overview, Contacts and Signals content. Contact email buttons copy original demo addresses; no messages are sent. The handover dialog, company sheets, row-action submenu and new-list dialog are actual local operations. No backend persistence is claimed.

An optional abort-aware `loadCompanies` prop exercises real loading, failure and retry from a caller-provided Promise. The synchronous original demo does not inject artificial waits or expose technical simulation switches in its product UI. The free DataGrid supplies loading skeletons and empty rows; a rejected loader supplies an error surface with Retry. The browser harness still needs to exercise these injected states.
