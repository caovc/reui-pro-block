## 1. Establish the actual reference and free-component map

- Record the real sidebar destinations, page identities and representative 1440/390 layouts before choosing row, table or form compositions.
- Match those surfaces to actual ReUI free Sidebar, Frame, DataGrid, chart, calendar, form and overlay implementations already present in this repository. Read the corresponding free examples and actual consumers first.
- Identify reusable domain helpers separately from UI primitives. Document gaps that require independent event calculations, schedule validation or workflow state; do not replace an available free component with custom controls.
- Use original Bricklane branding and permitted local artwork. Keep upstream private reference captures out of source, exports and Git; retain MIT, OFL and third-party notices.

## 2. Build feature modules in parallel

After the reference pass, assign disjoint files to three implementation slices:

1. Console shell, overview and service-budget views, including state derived from a shared independent event fixture.
2. Monitoring, event search/export and data-source management, using the existing free data components and real local interactions.
3. Release/deployment simulation, schedules and on-call views, with explicit navigation and reset boundaries.

The parent integrates profile/settings/auth screens and coordinates shared state, CSS imports and source metadata. Exact page ownership follows the observed route inventory; the list above does not invent destinations that have not been seen. Agents work privately, preserve unrelated work and report milestones to the sole Git writer.

## 3. Integrate a complete initial preview

- Register catalog, renderer/dispatcher, thumbnail and source targets only when the initial product is reviewable; do not advertise an empty nineteenth template.
- Keep the 18 existing defaults and routes intact. Audit family-level export collection before adding imports or dependencies, since it can change other templates' downloadable closure.
- Make Code, Copy, single-file download and the original project ZIP expose the actual implementation. Include every required engine asset, startup script and license.
- State which interactions are local demonstrations. Do not claim real monitoring, authentication enforcement or server persistence.

## 4. Verify and publish

Validate the necessary desktop/phone layout, keyboard/focus, data filtering/export, calculations and navigation state against concrete reference observations. Build the actual downloaded project without repairing its source, entry or configuration, then run its relevant interactions and verify raw members, generated assets and cleanup.

Run scoped formatting, required checks and the current CI gates. Commit and push each completed reviewable milestone through normal hooks; confirm the exact CI commit and Pages deployment separately. A nineteenth catalog entry alone does not complete fidelity work on this or the existing templates.
