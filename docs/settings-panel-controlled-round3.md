# Controlled account settings presentation

The original AccountSettingsDialog now consumes the extracted `SettingsPanel`, `SettingsRow`, `SettingsChoice` and `SettingsFields` from `src/blocks/application/dialog-variants/workspace/settings-panel.tsx`. It retains its launcher, draft/saved values, avatar and logo upload state, validation, local save result, and Cancel behavior. Cancel closes without discarding its draft, matching the previous block. No `application/forms.tsx`, Collaboration layout, source-target mapping, theme, global CSS or shared Tabs change is part of this milestone.

`SettingsPanel` is controlled through `sections`, `section/onSectionChange`, `value/onValueChange`, and `onSave(value)`. Optional `onDiscard` calls the owning application to restore its saved snapshot; it does not claim a save or discard on its own. Optional `onCancel`, disabled flags and header/footer renderers preserve dialog semantics and permit a page host. There are no account defaults, uploads, domain mutation, initial state or success toasts in the helper. Section children accept custom controls such as the original avatar upload; configured fields cover text, email, textarea, prefix/suffix input groups, selects and switches. Controls default to section-scoped IDs; `controlId` preserves required legacy IDs when supplied. The host owns field errors and saved/draft comparison.

The helper actually reuses the same free ReUI Field/FieldContent/FieldLabel/FieldDescription/FieldError/FieldGroup, Select (including SelectGroup), Switch, InputGroup, Tabs and ScrollArea implementations used by the existing block. Field descriptions and errors are associated with configured controls through `aria-describedby`. This extraction is from the existing local Pro Block; it does not copy an official paid block, invent BlockMeta, replace local artwork, or download original assets. Original Bricklane/local artwork and existing MIT/OFL notices remain in the exported dependency graph.

The existing dialog styling remains in `workspace/workspace.css`, imported by the original workspace block entry. A template host must load that scoped presentation CSS or supply its own panel/row styling. The helper does not import the whole block router or unrelated forms. It provides the shared controlled structure; it does not by itself reproduce every template's settings layout. Template adoption and controlled Frame section composition remain a separate coordinated milestone.

Validation and freeze evidence are recorded in the private ledger under `/tmp/bricklane-templates-round3/settings-panel-extraction/`. Baseline and candidate compare the same dialog entry, Profile state and Team/Default Role portal at 1440×844 and390×844, DPR1, light/dark. Portal font, grouping, density, selection and Tabs scrolling are measured, rather than patched locally. Root coordinates final source-target insertion, commit, push and CI.
