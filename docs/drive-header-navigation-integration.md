## Actual host behavior

Both `href` and ordinary activation use one typed route resolver. Views have
explicit destinations; files and folder records use their actual IDs. Filespace's
real tree-only Brand Library and Studio Operations nodes remain valid without
creating fake Folder records. The native Tree body is unchanged; its existing
node table was moved to one shared data module so the host can inspect its actual
namespace without adding non-component exports to the Tree component file.

Header name bindings are captured once per Drive mount. A renamed or deleted
record does not silently retarget a notification to a new record using its old
name. Unbound duplicate names produce explicit ambiguous feedback. Unknown paths,
malformed recognized links, missing IDs and removed records render an unavailable
state composed from the actual free Alert and Button. Empty filtered views are
valid. Existing unknown member details retain their own unavailable state.

The bare Filespace mount still starts at Favourites. Filebox still starts with its
original local Login and enters My Drive after ordinary sign-in. A copied explicit
Filebox destination survives sign-in. This remains front-end demo routing, not
remote authentication or authorization. Sign out navigates to Login, unmounting
Header consumers and resetting their local activity state; Back may return to the
retained local parent model, as before.

The file view derives from the current URL. Ordinary navigation pushes the native
hash once. Hash/popstate navigation clears transient search, selections and local
panels without pushing another history entry. Help and Notifications stay at the
same authenticated Header position through Profile, Workspace, Team, Billing and
Pricing, so their own state survives route changes and close/reopen.

Actual file actions and Copy Link use the same file/folder ID routes. Routed
previews record their same-mount origin in that native history entry. Close uses
Back only for an entry carrying this app's matching target/template/validated
origin metadata. A copied direct link has no known local predecessor and replaces
itself with a useful parent/My Drive destination instead of navigating blindly
into external browser history. Settings file actions open the file route once,
avoiding competing view and preview state updates.
