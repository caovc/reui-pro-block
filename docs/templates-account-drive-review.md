# Template account settings and Drive layout

Tempo and Mesh now open their actual five-section account settings from the native Sidebar and account menus. Their saved account identity is separate from the current Tasks search or Documents editor state. Filespace and Filebox now use the actual compact ReUI Sidebar and separate directory Sheet. This batch does not include the subsequent Echo, Flowly or Flux settings work.

## Reuse and behavior

The existing Pro `WorkspaceSettingsDialog` now delegates its real layout, rows, fields and media to the extracted controlled `SettingsPanel`. Tempo and Mesh reuse that same Panel, Rows and Fields implementation, with distinct section data and draft/saved models. The original Pro launcher keeps its original draft policy; the template consumers deliberately discard changes on Cancel, close and Escape. Save validates and commits the controlled draft, updates the account name/photo and preserves the current view. Profile media uses the existing official free file-upload hook through LocalAvatarUpload.

The supplied Pro WorkspaceMenu has a different hardcoded organization schema and no controlled identity/section callbacks. The template menus therefore compose existing free DropdownMenu groups, labels, items and native radio items. Theme controls update the real global store. Disabled organization-management and sign-out actions remain recorded limitations; no fake backend-success behavior is attached.

Tempo phone retains the native Sidebar Sheet beneath its Settings dialog; Escape closes the dialog to its actual trigger, then closes the Sheet to the header trigger. Mesh closes the Sheet before opening settings and returns focus to its header trigger. The native free SidebarNavigation gained an optional closeOnSelect policy for that distinction, preserving its default behavior. SidebarCollection gained a trailing presentation slot and SidebarTrigger honors its existing children contract; the default chevron, icon and close policy stay unchanged.

LocalAvatarUpload previously forwarded a parent update from the file hook's state updater, causing React to warn during render. It now notifies from an effect after a committed file-list change, retaining the latest callback and avoiding duplicate initial/StrictMode notifications. The official hook and preview lifecycle are not rewritten. Dedicated private regression evidence covers replacement/remove URL release and the original Pro launcher as well as both template consumers.

Workflow charts now use the existing ChartContainer, including its valid initial dimensions, instead of a bare ResponsiveContainer with initial−1 dimensions. Their measured dimensions, curve paths, tooltips and six settled chart screenshots remain identical; initial console warnings are eliminated. This reuses the same project chart implementation used by ReUI chart compositions.

Drive uses actual Sidebar Provider/Header/Content/Footer/Menu/RailButton/Trigger/Inset, free Sheet for its separate directory drawer, free ToggleGroup for view selection, and free Item rows for suggested folders. Details, dimensions and explicit remaining Drive settings differences are in `templates-drive-native-layout.md`.

## Production and source validation

A clean private candidate based on published `d8c6305` plus the exact mature runtime passed the original `npm run build` (`tsc -b && vite build`) with exit 0. Its immutable production preview passed 46 browser cases: 11 main account/focus cases, seven native Drive layout cases, two original Pro Settings launcher cases, and 26 existing workflow layout cases. Three additional existing Filespace business cases passed. No Echo, new Flowly Settings, Flux Settings or Lucent Settings changes are included.

The production Source UI passed four real download flows. For each template, the selected implementation text, clipboard, single-file download and complete project ZIP match the source bytes. Local source/CSS imports resolve and ReUI MIT, Inter OFL, attribution and bundled fonts remain present. Workflow archives have 227 files each, with 224 common bytes; Drive archives have 192 files each, with 189 common bytes. Only README, package metadata and Example entry differ within each pair.

The first font run exposed five failed external Unsplash avatar requests on Tempo desktop. The failure trace is retained. A separate approved one-file correction makes every workflow Person use the existing original `demoAvatar(name)` implementation, preserving the Avatar/Image/Fallback composition and dimensions. Its new immutable production build passed Vite with exit 0; its source tree differs from the typed main candidate only in that approved file. Actual Customize Default, Serif, Mono and Reset flows pass at both viewport sizes for Tempo and Mesh, including native menu/dialog/listbox fonts, saved identity and focus. No Unsplash requests or console errors/warnings occur. An added mobile avatar assertion initially matched a hidden desktop Sidebar image; the selector now checks actual visible images and the affected test passed without a runtime change. Both original failures remain recorded.

The updated Source UI and final local-avatar source also passed both Workflow four-way checks and produced fresh actual UI archives. Drive runtime and downloaded sources are unchanged from the four-way production proof. Both representative actual UI archives, Tempo 227 and Filespace 192, completed normal `npm install` and their unmodified original `npm run build` (`tsc --noEmit && vite build`) with exit 0. Vite finished in 875 ms and 656 ms respectively. Their original strict configurations were preserved. Existing dependency-level `use no memo` bundler notices remain in the complete logs. Mesh and Filebox share byte-identical runtime dependency trees with their respective representatives; separate builds are not claimed.

Detailed immutable build receipts, browser logs, original failures, downloaded archives and source manifests are under `/tmp/bricklane-templates-layout/`. Reference screenshots remain private audit material. Git submission, push and Pages completion are separate release-owner steps and are not implied by passing local checks.

## Remaining differences

Mesh account-menu horizontal offsets reflect the earlier parent footer-trigger geometry; the private audit records desktop+2px/mobile+8px rather than hiding them with negative margins. Menu email remains static while the v1 saved identity contract updates name/photo. New/manage organizations and sign out require separate product models. Drive's previous generic account/workspace/billing forms, some seed metadata and the existing grid/detail views remain follow-up work. The batch does not claim every template surface is fully reproduced.
